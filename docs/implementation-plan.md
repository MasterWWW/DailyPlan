# DailyPlan 个人每日工作计划工具实施计划

当一件事刚被打断时，用户还有几秒能留下半句话、一张截图或一段录音。首版要让这几秒足够创建一条待办。之后由桌面便签和上下班提醒把它带回眼前，直到用户勾选完成。

产品服务一位用户，按 Windows、macOS、iPhone 和 Android 四个客户端规划。首发交付可安装的 macOS 和 Android 应用，在 vivo X300 自带桌面验收小组件。首发期间为 Windows 和 iPhone 验证复用与同步协议，各自的可安装客户端安排在后续阶段。四端使用公司同一台 Docker 服务同步和转写，均可填写内网 IP 或本地名称。设备首次打开即使尚未配置服务器，也能离线记录。

## 快速记录和桌面查看

| 使用场景 | 用户动作 | 保存后的结果 |
| --- | --- | --- |
| Mac 上正忙，想起一句话 | 全局文字快捷键唤出已聚焦的输入框，打字，回车 | 生成今天的待办，输入框收起，焦点回到原先工作的窗口 |
| Mac 上看到需要跟进的内容 | 另一组全局截图快捷键唤出框选，松手保存。两组快捷键均可改 | 选区原图直接成为待办，可稍后补标题。按 Esc 取消时清单保持原样 |
| 从 vivo 桌面查看或完成 | 小组件直接列出未完成事项，点行首勾选，点标题查看详情 | 勾选立即写入本机，组件同步移除该行。能打开完整清单 |
| 从 vivo 桌面打字或说话 | 点一次“打字”即出现键盘，输入后提交即存。麦克风已授权时，点一次“语音”开始录，点“停止”即存 | 保存后返回桌面。录音立刻是一条可勾选、可回听的待办，文字稍后补入 |
| 手机上已有截图 | 在快速添加页点“选截图”，从系统选择器选图。已有待办的详情也可加图 | 复制原图到应用目录，默认可单独成项。列表显示缩略图，点开可看原图 |

录入时只需要文字、录音、截图三者之一。纯图片待办可显示为“截图 · 14:32”，取本次记录时间。首版跳过 OCR，直接保存和展示原图。

## 交互与视觉设计

**随手记下就能继续工作。** 快速记录默认今天、普通优先级，截止时间和紧急等级可以稍后在详情里改。Mac 文字录入全程可用键盘，截图框选松手即存。手机组件勾选一次即完成。保存成功以清单变化反馈，断网时简短提示“已存本机，待同步”。本地保存失败则保留输入，在原处给出“重试”。

**用排版和留白做出简洁大气的清单。** 今天页、Mac 便签和 vivo 小组件用同一份未完成清单。每行左侧是勾选框，标题最醒目，时间次一级。Mac 将截止时间沿同一右边线排齐，窗口变宽时把余量留在清单两侧。手机较窄时把时间移到标题下一行。同一任务的标题与时间靠近，相邻任务留出更大的行距。原图、录音和编辑操作在详情中展开，已完成记录在完整应用中查看。

**颜色只强调需要注意的地方。** 首版建议用系统中文字体、中性底色和一种操作强调色。紧急、逾期在对应任务旁配短文字和局部提示色，在浅色和深色外观下都能辨认。Mac 提醒面板突出任务和“已查看”，勾选框始终对应任务完成。

**手机小组件优先保住操作空间。** “打字”和“语音”直接可见。组件变窄或系统字号调大时，可以少显示几行，有更多事项时能点进完整清单。勾选区和打开详情的区域分开，勾选、打字和语音各保留至少 48 × 48 dp 的触控区域。[Android 触控尺寸指引](https://developer.android.com/develop/ui/compose/accessibility/api-defaults#minimum-touch-target-sizes)

## 哪些事每天出现，哪些事要弹窗

新建事项当天进入计划，默认当天截止。用户可以改为未来的日期，也可以指定具体时刻。只有日期时，到该工作时区的当天结束才算逾期。改了截止日，任务仍从创建当天起每天可见。跨天沿用原任务和原截止时间，勾选完成才从未完成清单移出。

| 时机 | 展示内容与动作 |
| --- | --- |
| 平时看桌面 | 展示全部未完成事项，包括下周才截止的事。紧急、临期和逾期用短文字标出 |
| 工作日上班 | Mac 在解锁后的桌面主动弹出紧急、临期和逾期事项，保留到用户点“已查看”。vivo 发本地通知，点开直达这份清单 |
| 工作日下班前 | Mac 和 vivo 都提醒查看当天仍挂在便签上的全部未完成事项，需优先处理的排在前面 |
| 点“已查看” | 收起这台设备的本次提醒。下一个时段会重新按完成状态计算。各设备独立提醒，完成状态跨端同步 |

**用周三交方案验收。** 周一新建“交方案”，把截止设为周三 15:00，当时就能在便签上看到。若一直未完成，周二上班、周二下班前、周三上班都要展示。周二早上点过“已查看”也一样。若周二下班前勾选完成，各设备同步后周三都跳过这件事。若周三仍未做完，周四上班列为逾期。昨天新建、沿用当天截止且漏做的事项，今天上班同样按逾期强提醒。

**首版的可调作息和默认规则**

- 设置工作日、工作时区、上下班时间和下班前的提前量，跨设备同步。初始建议周一至周五，上海时间 09:00 上班、18:00 下班、提前 15 分钟回顾。这些钟点可在设置里更改。
- “临期”从截止日的前一个工作日起算。周一到期的任务在通常的周五上下班时就会出现。截止落在休息日也取之前最近的工作日。紧急等级初值为普通，可标为紧急或非常紧急，两档都进入强提醒。
- 各设备用本地数据计算。按设备、工作日期和上下班时段记录展示与查看，避免解锁、重连或重启造成重复弹窗。进入时段后首次可用时补最近一次应看的清单，空清单跳过。改截止时间、勾选完成或收到同步更新时重新计算。

## 技术栈与四端分工

**手机端用 Kotlin Multiplatform + Compose Multiplatform，桌面端用 Rust + Tauri 2。** 手机端一门 Kotlin 贯穿 Android 与 iPhone，Android 首发，vivo X300 验收 Glance 小组件。桌面端一个 Rust 核心加一套 Vue 3 + TypeScript 界面，macOS 首发，Windows 复用同一工程。四端通过公司内网 Go 服务的版本化 `/v1` API 交换数据，业务规则与同步行为用语言无关的用例对齐。

选型首先看两个实际动作。vivo 小组件在主应用未打开时勾掉一项，可以直接调用共享的 Kotlin 代码，在同一笔本地事务里保存完成状态和待传操作。Mac 上按快捷键要能马上敲字，Tauri 的全局快捷键、托盘和常驻小窗口直接支撑，Rust 核心负责本地库、同步、截图和录音。这条组合的代价是桌面端与手机端各维护一份存储和同步实现，两边共享同一份协议描述和规则用例，用测试保证行为一致。[Glance 小组件](https://developer.android.com/develop/ui/compose/glance) · [Tauri 官方插件](https://tauri.app/plugin/)

| 平台与交付顺序 | 共用的应用界面 | 单独实现和验证的系统入口 |
| --- | --- | --- |
| macOS · 首发 | Tauri 2 工程，Vue 3 界面提供键盘优先的清单、便签和快速记录。Rust 核心承载本地库、待传队列与同步 | 菜单栏托盘、全局快捷键、焦点交还、窗口层级、系统截图与全屏选择框、麦克风录音、登录与唤醒提醒 |
| Windows · 后续接入 | 同一 Tauri 工程和 Rust 核心，在 Windows 上打包安装 | 托盘、全局快捷键、选区截图、系统提醒和唤醒。安装包在 Windows 主机验证。[Windows 快捷键](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey) |
| Android · 首发，vivo X300 验收 | 手机 Compose 页面，Android 宿主直接打开对应录入页 | Glance 桌面小组件、录音和选图授权、AlarmManager 本地提醒、WorkManager 持久同步。组件使用自己的布局，与主应用共用保存操作 |
| iPhone · 后续接入 | Xcode 宿主承载同一套手机 Compose 页面。点打字或语音直达录入页 | Swift / WidgetKit 与 App Intents 实现桌面清单和直接勾选，建议从 iOS 17 起验收。应用与组件通过 App Group 共用本机库和附件目录，本地通知、录音与选图接 iOS API。[Compose 接入 iOS 宿主](https://kotlinlang.org/docs/multiplatform/compose-swiftui-integration.html) · [Apple 小组件交互](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities) · [共享容器](https://developer.apple.com/documentation/widgetkit/developing-a-widgetkit-strategy) |

**代码放在哪里。** `apps/desktop/` 放 Tauri 2 工程，`src/` 是 Vue 3 + TypeScript 界面，`src-tauri/` 是 Rust 核心，包含 rusqlite 本地库、待传队列、同步实现、快捷键、截图、录音和托盘。`apps/mobile/` 放 KMP 工程，`shared/` 是手机端共享 Kotlin，包含任务规则、Room KMP 的 SQLite 结构与迁移、待传队列和同步实现，`androidApp/` 含 Glance 小组件，`iosApp/` 是 Xcode 宿主与 WidgetKit 小组件。`shared/protocol/` 放语言无关的 `/v1` OpenAPI 描述、JSON 请求与响应样例和规则用例，并声明附件接口的二进制格式。Go 服务、Rust 客户端和 Kotlin 客户端各自实现数据类型，用同一组样例检查日期、可选字段、游标和重复操作的兼容性。服务端独立管理权威数据、变更序号和备份格式。`server/` 放 Go 服务，`deploy/` 放 Docker Compose 配置。[Room 多平台指南](https://developer.android.com/kotlin/multiplatform/room)

**两端的规则保持一致。** 截止判断、临期与逾期分类、上下班提醒计算在 Rust 和 Kotlin 各实现一份。`shared/protocol/rules/` 放规则用例，每个用例给出一组作息、当前日期时刻和任务集合，并附期望的可见性与提醒结果。两端测试套件读取同一组用例并断言一致，新增规则时先加用例再改两端实现。

**工具和版本。** 手机端持久化用 Room KMP 和 SQLite，内网请求用 Ktor Client，实施时选相互兼容的稳定版本，在同一份 Gradle 版本目录固定 Kotlin、Compose、Room/KSP 和 Ktor。桌面端 Rust 核心用 rusqlite 管本地库、reqwest 做内网请求，官方能力提供全局快捷键、托盘、开机启动和单实例，截图用系统 `/usr/sbin/screencapture` 抓取当前显示器的无损 PNG，录音用 cpal 写 16 kHz 单声道 WAV。界面用 pnpm 和 Vite 构建。记录实际使用的 JDK、Gradle、Android SDK、Xcode、Rust 工具链和 Tauri 版本。Mac 与 Windows 分别生成各自的安装包，iPhone 的宿主和组件用 Xcode 构建。[Ktor 客户端引擎](https://ktor.io/docs/client-engines.html) · [Compose 版本兼容指南](https://kotlinlang.org/docs/multiplatform/compose-compatibility-and-versioning.html)

**由设备决定何时执行。** 平台层提供持久目录、凭据存储、截图和录音入口，以及提醒与同步的唤醒时机。两端各自实现显示哪些任务、保存哪些改动、下次从哪里继续同步。iPhone 上下班提醒走本地通知，回到前台且公司服务可达时立即补传，后台刷新按系统调度执行。Windows 客户端在登录、恢复使用或重新连回公司网络时补查。附件通过 ID 和内容摘要传输，设备文件路径只在本机使用。[Apple 后台调度](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app)

## 公司内网服务端选型

**首版服务端优先使用 MySQL（InnoDB），搭配 Go 内网 API。** Go 用标准库 `net/http` 和 `encoding/json` 提供 `/v1`，通过 `database/sql` 与 `go-sql-driver/mysql` 连接 MySQL。DailyPlan 使用独立数据库存储任务、完成状态、操作回执、变更日志和转写队列，所有业务表使用 InnoDB。截图和录音原件放在附件卷。各设备用本机 SQLite 保存离线副本，回公司后通过 Go API 同步。[Go HTTP 标准库](https://pkg.go.dev/net/http) · [Go MySQL 驱动](https://github.com/go-sql-driver/mysql)

**服务端维持 Go，桌面端使用 Rust 不影响这一选择。** Rust 的 Axum、Tokio 和 SQLx 也能连接 MySQL 提供同样的内网服务，后续若要把音频处理移进服务进程可再评估。当前的 HTTP 路由、事务和子进程调度用 Go 的标准接口就能表达清楚。采用同一个 whisper.cpp 模型时，识别速度应在公司电脑上用实际录音测量。[Axum](https://docs.rs/axum/latest/axum/) · [SQLx 支持的数据库](https://github.com/transact-rs/sqlx)

- **同步与附件。** 给 `op_id` 加唯一约束，重传返回原回执。每个数据集用一行同步状态保存最后发布的序号。所有会进入变更流的写入先用 `SELECT … FOR UPDATE` 锁定这行，在同一短事务里去重、更新数据、递增序号并写入变更，提交成功才确认。这样后提交的变更不会被已经前移的游标跳过。新设备用同一个只读 `REPEATABLE READ` 事务获取快照及同一时点的基准游标。附件在事务外流式写临时文件，校验长度及摘要后原子归档，再通过上述事务发布附件就位事件，并按 `attachment_id` 为录音唯一建转写作业。[InnoDB 锁定读](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html) · [InnoDB 一致性读](https://dev.mysql.com/doc/refman/8.4/en/innodb-consistent-read.html)
- **语音转写。** Go 后台任务从服务端数据库领取已提交的作业，在数据库事务外调用独立的 `whisper-cli` 子进程，结果写回原任务。首版一次处理一段，服务重启后重新领取中断的作业。Docker 镜像包含适合公司主机 CPU 架构的 Go 程序和 `whisper-cli`，本地挂载多语言模型，首测 `base`。记录真实中文样例的识别结果、排队时间和转写耗时。[Go 子进程接口](https://pkg.go.dev/os/exec) · [whisper.cpp](https://github.com/ggml-org/whisper.cpp) · [模型说明](https://github.com/ggml-org/whisper.cpp/blob/master/models/README.md)
- **换机恢复。** 同一 Go 程序提供 `serve`、`export`、`restore` 三个子命令。导出包含数据库逻辑备份及对应的截图、录音原件，按后文的迁移步骤在空卷恢复并核对摘要。

**服务端可以先独立验收。** 用三个模拟设备接入 `/v1`。设备 A 提交一条待办，模拟确认响应丢失，再用同一 `op_id` 重发。设备 B 从原游标拉取，应只看到一次新增。再让两个写事务交错执行，让第三台设备在它们提交期间拉取并推进游标，随后应能拉齐两条变更。接着上传一段录音，在转写过程中重启容器，确认结果仍属于原待办。最后把导出包恢复到空数据库和空附件卷，核对录音摘要、任务状态和转写结果。以上流程可先用 HTTP 集成测试跑通，再接真实客户端。

## 首发客户端的系统入口

macOS 和 Android 的系统入口应先在真机跑通。两端各自写入本机数据库，桌面便签和手机小组件从各自设备的本地库读取。

- **macOS** Tauri 桌面程序负责显示任务、独立桌面便签与输入框，Rust 核心持有本地库和同步。菜单栏托盘提供快速记录、便签开关和完整清单入口。全局快捷键用官方插件注册，窗口跨工作区显示和焦点交还经 objc2-app-kit 调用 AppKit。关闭主窗口只隐藏主清单，便签窗口继续保留在桌面并可直接勾选；便签可点标题打开完整清单详情。提供“登录时启动”，登录或唤醒时补查当日提醒。验证显示桌面、切换工作区和收起弹窗后的焦点。[AppKit 窗口行为](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/stationary) · [Tauri 全局快捷键](https://tauri.app/plugin/global-shortcut/) · [Tauri 开机启动](https://tauri.app/plugin/autostart/)
- **Mac 截图** Rust 调用系统 `/usr/sbin/screencapture` 抓取当前显示器的全屏无损 PNG，Vue 覆盖层让用户框选，按选区裁出原始像素，选区控件避开成图。首版以系统工具替代 `scap` 依赖，保持同等画质与多显示器行为。首次使用时请求屏幕捕捉权限。权限被拒或快捷键冲突时给出可操作的提示，文字入口继续可用。真机覆盖 Retina 缩放和外接显示器坐标。[Apple 屏幕捕捉示例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)
- **Mac 录音** Rust 经 cpal 采集麦克风，写成 16 kHz 单声道 16 位 PCM WAV 作为待办附件。首次使用时请求麦克风权限，权限被拒时文字入口继续可用，录音入口给出可操作的提示。
- **Android** 快速输入和录音 Activity 承载手机 Compose 页面，Glance 小组件通过手机端共享 Kotlin 模块读取 Room 清单。勾选走与应用相同的本地写入操作。录入按钮直接打开对应页面，分别聚焦输入或请求麦克风后录音。用 `PickVisualMedia` 选择截图，先将原图复制到本机持久目录，再向用户显示已保存。[Glance 交互](https://developer.android.com/develop/ui/compose/glance/user-interaction) · [Android 选图器及系统回退](https://developer.android.com/training/data-storage/shared/photo-picker)
- **手机提醒与后台工作** 本地 AlarmManager 安排上下班提醒，通知渠道允许用户调整提醒强度。按系统版本申请通知权限。需要准点且获系统授权时使用精确闹钟，否则使用系统允许的时间窗口，回到应用时补展示。开机、改作息或改系统时间后重排。WorkManager 负责可重试的内网同步与附件传输。把 X300 的系统版本、锁屏、省电设置和提醒实际到达时间写入验收记录。[Android 闹钟调度](https://developer.android.com/develop/background-work/services/alarms) · [通知权限](https://developer.android.com/develop/ui/compose/notifications/notification-permission) · [持久后台任务](https://developer.android.com/develop/background-work/background-tasks/persistent)

## 离线保存与跨端同步协议

| 数据 | 实现约定 |
| --- | --- |
| 待办 | 客户端生成稳定的 `task_id`。分别保存创建日、截止日期及可选时刻、紧急等级、手动文字和完成状态。只有日期的截止日单独存储，带时刻的值按工作时区解释 |
| 附件 | 每份原图或录音有独立 `attachment_id`、所属待办、类型、媒体格式、字节数和 SHA-256。原件持久保存，缩略图可重建。语音另存转写状态和原始转写文字 |
| 本地待传操作 | 同一事务内更新本地任务并写入带 `op_id` 的待传队列。图片和录音先写临时文件、原子归档，再提交引用。只有成功落盘才显示已保存，重启后继续传 |
| 服务端变更 | 操作去重、字段更新和分配递增变更序号在同一事务完成。服务端持有数据集标识、恢复版本号、变更记录和工作设置。每次客户端安装生成独立的 `device_id`，各自保存已应用的游标 |

1. **何时连接。** 配置、启动、回到前台、网络变化和本地操作都会触发连接。只有配置的服务可达且认证通过才传数据。连着蜂窝网络或家庭 Wi-Fi 却到不了公司服务时，仍在本机排队。设置页显示最近成功时间、待同步数量和重试入口。
2. **如何更新各端。** `GET /v1/status` 握手，`POST /v1/operations` 按本地顺序提交字段变更，`GET /v1/changes?after=…` 分页拉取。`GET /v1/snapshot` 返回同一时点的数据和基准游标。每页数据与新游标在同一事务落库，待传操作收到确认后才出队。建议桌面便签运行中、手机应用在前台时每 15 秒自动拉取增量，连接失败则逐步延长重试间隔。同一内网中各活跃客户端的联调目标为 30 秒内看到文字或状态变化。手机后台在系统给出执行机会时补齐，打开应用或操作组件也触发同步。拉取成功后刷新本机清单，并请求系统更新小组件。
3. **并发与断线。** 发送明确的字段值，例如“设为已完成”。重复提交同一 `op_id` 返回原确认。改标题和勾完成可合并，同一字段发生竞争时取服务端最后接收的有效操作。拉取时保留本机尚未确认的字段修改。断线、服务重启、多台设备同时编辑和响应丢失都按此规则重试。
4. **附件与转写。** 用 `PUT/GET /v1/attachments/{id}` 传原件。已确认任务后可独立上传附件，服务端校验长度和摘要，原件就位才确认，并登记一条变更供其他设备获取原图或录音。传输中断可重传同一 ID。客户端保留尚未获确认的原件。接收设备先显示待办，原件到齐后可离线查看或回听。

**两端各实现一份客户端。** Rust 与 Kotlin 各自实现待传队列、增量拉取和附件传输，都对照 `shared/protocol` 的同一份描述与样例。规则与提醒计算用规则用例对齐，协议行为用服务端模拟设备用例和两端各自的集成测试对齐。改动协议时先更新 OpenAPI 与样例，再改 Go、Rust、Kotlin 三份实现。

录音停止时，先以“语音待办 · 记录时间”显示。公司服务收到完整音频后，自动排队并用中文模型转写，结果写回**同一个任务**。Mac 与手机录音统一输出 16 kHz 单声道 16 位 PCM WAV 后再上传，作为转写输入。转写文字替换占位标题。用户已手动命名时，保留标题，转写文字进详情。用户已经勾选时，保留完成状态。`title_source` 表示标题是否仍为占位，转写回写后即视为最终标题；转写原文与状态保存在附件的 `transcript` 字段，不丢失来源。工作进程中断后重领未完成作业，同一附件只产生一份结果。失败时保留录音并显示可重试状态。截图走原件传输通道，只有录音会进入转写队列。

## 内网部署和恢复到新服务器

**DailyPlan 单独部署专用 MySQL 实例。** 在公司同一台电脑上，用一份 Docker Compose 配置运行 `docker compose up -d`，启动以下两个服务。

- `api` 运行 Go 同步接口和语音转写任务。API 端口发布到公司内网，截图和录音保存在独立附件卷。
- `db` 运行 DailyPlan 专用的 MySQL/InnoDB，数据库目录挂独立持久卷。`api` 使用应用专属账号通过 Compose 内部网络连接 `db`。

记录实际 MySQL 版本，并使用与其兼容的导出和导入工具。数据库凭据和 API 访问令牌通过部署环境配置。

客户端设置页接受带协议和端口的 IP 或主机名，并支持测试连接，例如 `http://192.168.10.20:8787` 或公司 DNS 中可解析的 `http://dailyplan.office.example:8787`。四端填写 Go API 的宿主机地址。`.local` 名称依赖局域网 mDNS 解析，首发用 Mac 和 X300 实测实际名称，后续客户端复用同一接入用例。[Docker Compose 网络](https://docs.docker.com/compose/how-tos/networking/)

单用户使用一枚部署时生成的访问令牌，客户端保存在系统保护的存储里。支持公司受信 HTTPS。使用内网 HTTP 时，仅向明确配置的内网端点发送请求，配置对应平台的本地网络策略。首次连接时按实际操作系统和 Android target SDK 处理局域网权限。连接测试区分名称解析失败、服务不可达、无权限和令牌失效，本地数据随时可用。[Apple 本地网络隐私](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) · [Android 局域网权限](https://developer.android.com/privacy-and-security/local-network-permission)

**导出的验收标准是能换服务器。** Go 程序提供 `export` 和 `restore` 子命令。随服务准备兼容的 `mysqldump` 和 `mysql` 客户端工具。`export` 用 `mysqldump --single-transaction` 导出 DailyPlan 专属库中的 InnoDB 表，`restore` 用 `mysql` 导入新机上预建的空库。迁移时先让可达设备同步，再将旧 DailyPlan 服务切到只读，暂停本应用的后台结果写入、文件清理及表结构迁移，等在途写入完成。在这段一致的只读窗口内导出数据库、列出已确认的附件并打包其原件。备份清单记录数据库类型与版本、应用数据结构版本、转写模型版本与摘要，以及附件 ID 与摘要。任务、完成记录、作息、转写结果或待处理状态、变更游标及操作去重记录都随库导出。清单和原件校验通过后再发布完整备份包。[MySQL 逻辑导出](https://dev.mysql.com/doc/refman/8.4/en/mysqldump.html)

新机按备份清单准备兼容版本的 MySQL、应用账号、匹配的转写模型与访问令牌。向独立空库和空附件目录恢复，校验数据库版本、任务数、附件关联及每份原件的摘要，通过后切换 Go 服务连接。损坏包停在校验阶段，原有数据保持可用。恢复时保留数据集标识，为本次恢复生成新的版本号。各客户端改地址后检测到版本号变化，重新获取一致快照和基准游标，保留并重放本机待传操作、录音和图片。若离线编辑引用的任务未进入该快照，用设备保留的任务内容补建同一 ID。新机随后继续处理尚未转写的录音。备份的时间边界是导出时服务器已收到的数据。

## 实施顺序与验收

服务端先用上述双设备用例验证 Go API，客户端系统入口可同时验证。下表从首发客户端开发一直覆盖到联调和换机交付。

| 阶段 | 接手 agent 的交付物 | 阶段验收 |
| --- | --- | --- |
| 1　验证系统入口 | 用 `apps/desktop/` 做 macOS 可安装样机，用 `apps/mobile/` 做 Android 可安装样机，都调用各自本地模块的新建与完成操作 | 在其他 Mac 应用中唤起输入框和框选截图。用 X300 自带桌面添加组件，检查打字、勾选、录音和通知，记录系统版本与实际授权 |
| 2　本地可用 | 在两端本地模块实现数据库与待办规则，首发两端各接入今天页和截图、录音保存 | 断网后使用所有录入入口，重启仍能找回文字、截图、录音及勾选状态。Mac 取消框选后无空任务。手机从相册选图并保存，移走相册中的测试副本后仍能打开原图 |
| 3　公司内网同步 | 用一份 Docker Compose 启动 `api` 和专用 MySQL 服务 `db`。首发客户端通过内网地址、令牌接入 Go `/v1`，联调增量同步和附件接口 | IP 与实际本地名称都能连接。两端离线分别改标题和完成状态，回公司后自动合并。中途断开上传、重发已接收的操作，核对只有一条待办、一份正确原件。保留持久卷重建容器后，原任务仍可查、附件仍可打开 |
| 4　录音自动转文字 | 接入持久作业队列、本地模型和转写结果同步 | X300 离线录“明早给客户回电话”，重启后回到内网，Mac 上原任务出现文字并可回听。中途停工作进程或手动改标题，再恢复处理，核对标题、完成状态及任务数量 |
| 5　上下班提醒 | 两端按规则用例计算工作日和待提醒任务，分别实现 Mac 弹窗和 Android 本地通知 | 用可控时间逐个跑周二上班、周二下班前、周三上班，以及漏做次日、周末跨越、已完成和空清单。在真机另测锁屏、唤醒、通知关闭与恢复 |
| 6　换机交付 | 交付 Mac 安装包、Android APK、Docker Compose 配置、模型准备说明、导出恢复命令及简短使用说明 | 在同类空数据库和空附件卷中恢复，核对任务数、截止与完成状态、原件哈希、转写及作息。损坏测试包中的图片应在启用前报出文件名。带离线新记录的客户端改连新机后可补传，两端一致 |

**先验证平台能力风险。** 阶段 1 在 Mac 使用发布构建，保持便签运行，从其他应用连续唤起 20 次并立即输入“核对运费”。记录按键到获得输入焦点的中位数与 P95、是否丢首字、关闭后焦点位置，以及空闲十分钟的进程内存与 CPU。成功表现是每次都能直接输入并回到原窗口。在 X300 让主应用退到后台、断开网络，从组件新增、录音和勾选，再重开检查记录。另记录锁屏省电状态的提醒到达时间。性能数值由真机给出。出现问题时先定位窗口激活、系统调度或本地写入的耗时。

**首发的四端预备验收。** 在 macOS 构建机用 iPhone 模拟器宿主打开共用的手机清单页，验证调用本地新建和完成。在 Rust 核心用独立目录跑本地库的离线读写用例。阶段 3 用四个设备 ID 联调同一服务。前两台设备离线改标题和勾完成，后两台从快照加入，再拉增量，核对四份清单、游标和附件摘要。分别记录两端构建、规则用例、协议测试与实机结果。Windows 安装、iPhone 小组件及两者的后台行为在各自开发阶段上机验证。

**后续客户端的实机验收。** iPhone 从小组件勾选、离线录音并从相册选图，用本地名称连回公司后核对原件和转写。Windows 从其他应用用快捷键录文字、框选截图，再测锁屏恢复后的桌面提醒和快捷键冲突。两个客户端均可分别接入已经交付的 Mac 和 vivo。四端齐备后，用 Windows 新建截图、iPhone 勾完成，检查 Mac 与 vivo 收到更新。换服务器恢复后，再核对四端的完成状态和原图摘要。

**界面验收。** 阶段 2 在 Mac 便签和 vivo X300 小组件放入普通、已逾期和长标题待办，分别用默认与放大字号查看。核对任务和状态可读、录入入口可见，点标题打开详情、点勾选框只完成对应任务。按前表逐个走完录入流程，记录首次授权后的实际操作步数和两端截图。阶段 5 再点一次“已查看”，确认弹窗收起、任务仍在。

最终演示从公司以外开始。在 Mac 截一张需要跟进的内容，在 vivo 离线添一段语音和一张手机截图。回公司后，检查两端都能打开两张原图，录音文字出现在原待办上。下班只点“已查看”，次日上班仍应看到昨天未完成的项。在手机组件勾掉其中一项，Mac 随同步移除。最后从导出包恢复，核对这一项仍为已完成，两张截图和录音仍可打开。
