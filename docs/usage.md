# 使用说明

## 启动服务

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

服务停止但保留数据：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env down
```

不要使用 `down -v`，除非明确要删除 MySQL 和全部附件。

## 每天的使用节奏

1. 上班后打开 Mac 端或手机端，先处理标为“已逾期”“紧急”“临期”的项。
2. 在电脑上用 `Command+Shift+Space` 快速记录，用 `Command+Shift+Enter` 框选截图。
3. Mac 桌面便签保持常驻，可直接勾选；关闭主窗口后在便签上继续操作，点标题可回到完整清单。
4. 在手机上用今天页输入、选图或录音，所有内容先落本地。
5. 完成后点勾选框；点击标题进入详情修改标题、日期、时间和优先级。
6. 下班前收到提醒时，处理或保留待办，点“已查看”。已查看不会完成任务，次日仍会保留未完成项。
7. 回到内网后两端自动同步；手机小组件可不开主应用直接完成任务。

## 排序与提醒

待办按以下顺序展示：

1. 已逾期。
2. 紧急/非常紧急。
3. 临期。
4. 其他未完成项。

同一组内按截止时间排序。未设置具体时间的截止日期按当天 23:59:59 计算。

提醒规则：

- 仅在所选工作日提醒。
- 上班时间到达后触发上午提醒，只包含逾期、紧急和临期事项。
- 下班时间减去“下班前回顾”分钟数后触发傍晚提醒，包含全部未完成事项。
- 当天同一时段只提醒一次；点“已查看”或 Android 通知已投递后记录。Android 通知和今天页提醒卡片都提供“已查看”，点击后收起本设备的本次提醒。
- 清单为空、全部完成或当天不是工作日时不提醒。

## 多端同步与离线

- 文字、完成状态、标题和设置使用幂等操作 ID 补传；重复发送不会生成第二份待办。
- 附件先校验大小和 SHA-256，再上传原图或 WAV。
- 服务端恢复或切换数据集后，客户端检测到数据集/恢复版本变化会重新拉快照。
- 同一字段发生离线冲突时，以最后被服务端接受的操作为准。建议冲突后核对标题和完成状态。

## 快速验证连接

```bash
set -a
source deploy/.env
set +a
curl -fsS \
  -H "Authorization: Bearer ${DAILYPLAN_API_TOKEN}" \
  "http://127.0.0.1:${DAILYPLAN_PORT:-8787}/v1/status"
```

客户端设置页的“测试连接”与“立即同步”使用同一套协议。

## 备份

导出和恢复的完整命令见 [部署说明](deployment.md)。建议在停止 API 后导出，并把整个备份目录复制到另一块磁盘。恢复只能进入空 MySQL 数据库和空附件卷。
